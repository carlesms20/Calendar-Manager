1. Nuevo paso en Morning Workflow

Después de:

Detectar prioridades.

Añadir:

Conversation Analysis

El Executive Assistant deberá analizar todas las tareas activas para identificar si varias requieren una conversación con la misma persona.

El análisis será independiente de:

* departamento;
* proyecto;
* prioridad;
* origen de la tarea.

⸻

2. Nuevo paso obligatorio

Conversation Grouping

Cuando varias tareas compartan el mismo interlocutor, el sistema deberá agruparlas automáticamente.

No deberá mostrar varias tareas independientes si todas pueden resolverse durante una misma conversación.

⸻

3. Executive Meeting Planning

Después de agrupar conversaciones, el sistema deberá generar automáticamente una propuesta de reunión ejecutiva.

Cada propuesta incluirá:

* participante;
* duración estimada;
* prioridad;
* agenda;
* tareas relacionadas;
* resultado esperado.

⸻

4. Calendar Proposal

Antes de finalizar el Executive Plan diario, el sistema deberá consultar Google Calendar para localizar el mejor horario disponible.

La propuesta deberá respetar:

* horario laboral;
* bloques estratégicos;
* reuniones existentes;
* buffers;
* trabajo profundo.

⸻

5. CEO Confirmation

Añadir una regla general para todo el workflow:

Ninguna reunión podrá incorporarse a Google Calendar sin confirmación explícita del CEO.

Siempre deberá seguirse:

Analyse → Propose → Confirm → Execute

⸻

6. Agenda Preparation

Antes de cada reunión, el Executive Assistant deberá preparar automáticamente una agenda.

Cada punto contendrá:

* tarea relacionada;
* objetivo;
* decisión esperada;
* documentación necesaria;
* tiempo estimado.

⸻

7. Executive Plan

El Executive Plan dejará de mostrar únicamente tareas.

Ahora incluirá también:

* reuniones propuestas;
* reuniones confirmadas;
* conversaciones agrupadas;
* bloques estratégicos;
* trabajo profundo;
* Quick Actions;
* Waiting;
* Delegated Work.

⸻

8. Working Block Workflow

Cuando comience un bloque de conversación, el Executive Assistant deberá presentar automáticamente:

* la agenda;
* las decisiones pendientes;
* los documentos necesarios;
* las tareas relacionadas.

El CEO no deberá buscar información antes de la reunión.

⸻

9. Checkpoint Workflow

Durante los checkpoints del día, el sistema deberá comprobar:

* reuniones pendientes de confirmar;
* reuniones ya realizadas;
* decisiones obtenidas;
* nuevas tareas generadas;
* Waiting creados;
* delegaciones pendientes.

⸻

10. Evening Review

Al finalizar el día, además de la revisión habitual, el sistema deberá verificar:

* reuniones realizadas;
* reuniones aplazadas;
* reuniones canceladas;
* tareas resueltas durante las reuniones;
* decisiones tomadas;
* nuevas acciones generadas.

⸻

11. Waiting Workflow

Si una reunión queda pendiente por falta de disponibilidad de alguna persona, el sistema deberá crear automáticamente un Waiting Item con:

* Waiting For;
* Since;
* Next Follow-up;
* Expected Response;
* Next Action if no response.

⸻

12. Follow-up Workflow

Después de una reunión ejecutiva, el Executive Assistant deberá generar automáticamente los seguimientos necesarios.

Cada seguimiento deberá indicar:

* responsable;
* siguiente acción;
* fecha de revisión;
* dependencia;
* prioridad.

⸻

13. Nueva regla de Executive Workflow

Añadir al final del documento:

Executive Conversation Principle

Siempre que dos o más tareas puedan resolverse mediante una única conversación con la misma persona, el Executive Assistant deberá transformarlas en una única reunión ejecutiva.

La planificación diaria debe minimizar el número de interrupciones y cambios de contexto.

El objetivo no es completar más tareas.

El objetivo es utilizar el menor tiempo ejecutivo posible para generar el mayor impacto empresarial.
