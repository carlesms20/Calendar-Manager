# Principios del Roadmap

## RULE-001 — Orden obligatorio

Las fases deben desarrollarse en el orden definido por este documento.

No pueden alterarse las dependencias.

---

## RULE-002 — Criterio de bloqueo

Una fase únicamente puede declararse **LOCK** cuando todos sus documentos hayan superado sus Acceptance Criteria.

---

## RULE-003 — Documentos LOCK

Un documento LOCK no puede modificarse salvo que exista una necesidad arquitectónica relacionada con:

- compatibilidad;
- integridad;
- seguridad;
- consistencia del sistema;
- fuente única de verdad.

---

## RULE-004 — Evolución del sistema

No se eliminan fases.

Las mejoras se incorporan mediante:

- nuevos documentos;
- Addendums;
- nuevas fases.

---

## RULE-005 — Compatibilidad

Toda nueva funcionalidad debe ser compatible con todas las fases anteriores.

Nunca puede romper el comportamiento existente.

# Acceptance Criteria

El Master Roadmap será correcto cuando:

- exista una única arquitectura oficial;
- todas las fases tengan un objetivo definido;
- todos los documentos pertenezcan a una fase concreta;
- las dependencias sean explícitas;
- el orden de evolución sea único;
- cualquier nueva funcionalidad pueda ubicarse sin romper la arquitectura existente.
